# Parcel Pulse — Fictional Agent-First Example

This entirely fictional example shows the shape of a `NEW_PROJECT` pass. It is
not a prescribed architecture and contains no real people, companies, endpoints
or operational data.

## Scenario

A human asks for a small product that lets a support team see delayed parcel
events without manually checking multiple carrier portals.

## Walkthrough

1. Human input: [`INPUT.md`](INPUT.md)
2. Agent separates evidence and uncertainty: [`DISCOVERY_BRIEF.md`](DISCOVERY_BRIEF.md)
3. Human reviews options: [`PROPOSAL.md`](PROPOSAL.md)
4. Accepted product context: [`docs/contexts/PRODUCT.md`](docs/contexts/PRODUCT.md)
5. Accepted architecture and Mermaid view: [`docs/contexts/ARCHITECTURE.md`](docs/contexts/ARCHITECTURE.md)
6. Consequential decision: [`docs/adr/0001-local-first-prototype.md`](docs/adr/0001-local-first-prototype.md)

The example stops before implementation. Its purpose is to demonstrate that an
agent does not turn the first idea into code or pretend its proposal is approved.
