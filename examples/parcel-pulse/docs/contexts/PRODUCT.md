# Product Context — Parcel Pulse

## Problem

Support lacks a single view of fictional parcel events that may need attention.

## Users

Internal support agents evaluating the prototype workflow.

## MVP

- load a fictional parcel dataset;
- evaluate the accepted stage-specific age thresholds;
- show parcels currently considered delayed;
- make the reason visible.

## Non-goals

- live carrier integration;
- production credentials or customer data;
- notifications, acknowledgement or case management;
- universal delay rules.

## Product invariant

A delayed result must explain which accepted threshold was exceeded.

## Validation

A support reviewer can inspect representative fictional cases and explain why
each parcel is or is not flagged.
