---
name: delivery-slice-mapping
description: Map a meaningful feature, bug, risky change or resumed task into the smallest coherent delivery slice before editing. Use when scope, ownership or validation needs to be explicit.
---

1. Read `AGENTS.md`, `docs/PROJECT_INDEX.md`, the minimum domain owner and `docs/checklists/CHANGE_IMPACT.md` when risk/cross-cutting.
2. Synthesize:
   - problem/outcome;
   - hypothesis when relevant;
   - MVP;
   - non-goals;
   - happy path;
   - unhappy path;
   - edge cases;
   - owners touched;
   - risks;
   - validation.
3. Compare the snapshot with code/tests and the active work item.
4. Resolve material divergence before implementation.
5. Work from the snapshot instead of repeatedly reopening broad context.
6. Leave a concise continuation point on closeout.
